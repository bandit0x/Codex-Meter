Nielsen 分数说明基础可用性没有崩坏，不代表视觉还原通过。当前失败的是用户已明确批准的材质、构图精度与动效契约，属于发布阻塞。

## Design Specificity Verdict

**独立设计评估：** 双等权液舱、刻度、重置时间与共享页脚具有很强产品特异性；它不是可换皮到任意 SaaS 的通用卡片。实装保留了“单胶囊 + 等权双字段”骨架，但把批准稿的内舱曲面、折射边、弯曲液面和细腻光学轮廓压成了扁平深色矩形。结果从“精密光学容量仪器”退成“暗色配额组件”。

**确定性扫描：** `detect.mjs --json src` 返回 `[]`、退出码 0。这个 clean 只表示规则未命中，不表示设计还原。扫描外的源码映射发现：成功返回的 `sourceState: "stale"` 从未被 UI 消费；默认 glass opacity `0.92` 偏离设计 `0.76`；30px 二级控件低于设计门槛；缓存刷新、click-through 失败和偏好保存失败缺反馈；当前没有持续液体漂移，只有 260ms 液位 transition 和 loading shimmer。

**Visual overlays：** 当前没有可变浏览器自动化标签页，未注入 overlay。使用的 fallback 是真实打包 Tauri 截图、批准 PNG、源代码和 exact-size HTML/CSS 渲染。

## Overall Impression

最大问题不是“少几层阴影”，而是验收方法错了：我只检查了单胶囊、双等权、状态存在等结构条件，没有把材质层、像素比例、光线与动效列成必须逐项通过的验收项。于是 detector clean 和功能全绿掩盖了肉眼可见的巨大差距。

## What's Working

1. 5 HOUR 与 WEEK 使用相同结构、字号、面积和刻度，真正同为最高级别。
2. loading、healthy、failed 与 stale 没有跳成另一套产品，完整失败有原因、诊断码和唯一 Retry。
3. 真实 Tauri 透明窗口、acrylic、WebView2 和只读 Codex 数据闭环已经跑通，可保留为后端与壳层基础。

## Priority Issues

### [P1] 实装没有达到批准稿的光学液态玻璃材质

**为什么重要：** 这是用户明确锁定的视觉承诺，也是这个小工具的产品辨识度。当前外壳灰白阴影更抢眼，内舱没有足够折射深度，中缝只是分隔线，液面像矩形渐变填充。

**修复：** 用精确 600×260 工程稿规定外壳、内舱、折射缝、meniscus、刻度和页脚的像素关系；在深/浅桌面各自验收。减少厚灰影，把能量转移到内缘折射、液面曲线和接触高光。

**Suggested command:** `$impeccable polish`

### [P1] 动效不是“弱”，而是没有被设计成契约

**为什么重要：** 当前只有数据变化的 260ms clip-path 和 loading shimmer；静态健康态没有液体呼吸、meniscus 漂移、边缘 glint、数字更新或 expand 的空间连续性。用户要求的“液态”因此停在静态贴图。

**修复：** 把启动、液体 settle、低频 drift、边缘 glint、刷新、数值更新、expand/collapse、loading 和 failure morph 写成时长、曲线、属性与 reduced-motion 的完整 contract；后续截图之外再做真实动态验收。

**Suggested command:** `$impeccable animate`

### [P1] 局部数据不可用与 stale 会损坏“可信仪器”定位

**为什么重要：** `—% LEFT` 与 `Updated now` 并存让未知数据看起来像排版损坏；`sourceState: stale` 成功返回时会被当作 healthy。

**修复：** 每个窗口使用明确 `available / unavailable / stale`；不可用不显示 `% LEFT`，共享页脚说明哪些窗口新鲜；消费 `sourceState` 并提供恢复动作。

**Suggested command:** `$impeccable harden` + `$impeccable clarify`

### [P1] 批准状态板中的 collapsed 没有实现

**为什么重要：** 常驻桌面工具必须能低干扰长期存在；当前只有 footer 内容切换，没有独立 collapsed/compact/expanded 布局和窗口尺寸契约。

**修复：** 建立三个明确布局状态，并通过 Tauri 同步 520×96、600×260、600×320 的窗口尺寸；禁止失焦后自动跳尺寸。

**Suggested command:** `$impeccable adapt` + `$impeccable layout`

### [P2] 二级控制的可发现性、焦点与反馈不稳

**为什么重要：** 右键设置和过小箭头依赖猜测；expanded footer 拥挤；设置没有 dialog/Esc/focus-return；缓存刷新没有 busy；30px 控件低于既定 32px 门槛。

**修复：** 保持只有一个可见主控件，但扩展到 40×40 命中区、使用正规 SVG chevron、加入 tooltip 与一致 focus ring；expanded 增高而不是把所有按钮塞一行；补刷新和失败反馈。

**Suggested command:** `$impeccable audit` + `$impeccable harden`

## Persona Red Flags

**Alex（高频用户）：** 能在一秒内读完两个额度，但找刷新/穿透/设置需要先发现小箭头；没有 collapsed，长期占屏后更可能直接关掉；缓存刷新没有立即反馈。

**Sam（键盘/低视力）：** 设置依赖右键且不是 dialog；Esc、焦点进入/恢复、统一 focus ring 缺失；`—% LEFT` 的读屏语义错误；loading 和自动刷新未可靠 announce。

## Minor Observations

- `%` 与液位方向正确，但实际液位范围过度占用数字区域；新稿应使用校准后的可视轨道，而不是让 76% 液面顶到标题。
- expanded 的中英混排与到期信息应有固定语言策略。
- Unicode `↗/↙` 容易被理解为外部打开，应该换一致的 SVG expand/collapse 图标。
- 完整 failure 的诊断码出现两次，没有必要。

## Questions to Consider

1. 这个物件应优先像“透明桌面玻璃”，还是像“在任意桌面上都稳定可读的自发光光学仪器”？当前推荐后者为主、背景采样为辅。
2. collapsed 是否只由用户主动切换？当前推荐主动切换，不在失焦时自动收缩。
3. 当某个额度窗口缺失时，是否有可靠协议语义区分“套餐没有”与“读取异常”？在没有证据前，UI 应诚实显示“数据不可用”，不能自行解释。
